# Paranoidal Launcher

Лаунчер сборки Factorio **Paranoidal**: один exe, который ставит и обновляет моды сборки с GitHub, проверяет игру
и запускает её. Git, токены и настройки игроку не нужны.

**Скачать:** [Releases](../../releases) → `ParanoidalLauncher.exe`, прямая ссылка на последнюю версию:
https://github.com/FactorioParanoidal/paranoidal-launcher/releases/latest/download/ParanoidalLauncher.exe.
Положите его в папку Factorio 2.0.77 и запустите. Если запустить из другого места, лаунчер 1.2.0+ сам переедет в
папку игры. Если Windows пишет «Windows защитила ваш компьютер», нажмите «Подробнее» → «Выполнить в любом случае»
(у exe нет цифровой подписи).

История изменений — `CHANGELOG.md`. Агентам и разработчикам: начните с `AGENTS.md`.

## Что умеет

- Ставит и обновляет папку `mods` до ветки `pre_release_2.0` репозитория
  [FactorioParanoidal/ParanoidalModpack](https://github.com/FactorioParanoidal/ParanoidalModpack). Скачивается
  только разница.
- Проверяет игру: нужна Factorio 2.0.77 с файлами дополнений Space Age. Запускает её с `--mod-directory`.
- «Проверить файлы» — сверяет всю сборку с GitHub побайтно и докачивает отличия.
- Узнаёт сборку, которая уже лежит в папке (скопирована, распакована, получена по сети), без интернета.
- «Откатить» / «Вернуть» — шаг назад и вперёд без интернета. «Не менять версию» и «Версия хоста…» — играть на той
  же версии, что хост.
- «Отчёт о проблеме» — ZIP для Discord на рабочий стол.
- Обновляется сам: показывает все новые версии со списком изменений и советует обновиться.
- «📖 Гайд» — иллюстрированный гайд по сборке одним HTML-файлом рядом с лаунчером; обновляется вместе со сборкой.
- Переезжает в папку игры, если запущен из другого места; «Ярлыки» — рабочий стол и меню «Пуск».
- Строка диагностики загрузки: сколько грузилась игра и сработал ли кэш.
- Интерфейс на русском и английском.
- Работает без интернета: играть, откатываться и делать отчёт можно и так.

## Версии

- Версия задаётся в **одном месте**: `AppInfo.Version` в `src/AppInfo.cs`. Заголовок окна, журнал, `crash.txt`,
  `sync-log.txt`, версия exe и его манифест берут её оттуда. Больше нигде её не пишите.
- **Любое изменение, после которого получается другой exe, — новая версия** (`x.y.Z` для исправлений и мелочей,
  `x.Y.0` для крупного) и новый раздел в начале `CHANGELOG.md` на русском.
- `build.ps1` следит за этим: `CHANGELOG.md` должен начинаться с `## <версия>`, а другой exe под уже собранной
  версией не соберётся. Сборка детерминированная: одни исходники — один и тот же exe. `-SameVersion` пересобирает
  текущую версию, пока её никому не отдали.
- Правка только комментариев или документов даёт тот же exe — новая версия не нужна.

## Публикация

- Только по команде владельца. Сначала `powershell -ExecutionPolicy Bypass -File publish.ps1 -DryRun`: всё, кроме
  тега, пуша и загрузки; собирает в `obj\dryrun\`.
- `publish.ps1`: чистая `main`, не отстаёт от `origin` → тега `vX.Y.Z` ещё нет → `build.ps1` → самопроверка Harness →
  `tools\release-manifest.ps1` → аннотированный тег → пуш `main` и тега → `gh release create` (exe + `release.json`,
  заметки — раздел CHANGELOG, отметка latest) → проверка, что `releases/latest/download/release.json` отдаёт эту версию.
- Токен для `gh` берётся из Git Credential Manager (или `GH_TOKEN`) и не печатается.

## Где лаунчер ищет обновления

Всё — в `AppInfo` (`Owner`, `RepoName`/`Branch`, `LauncherRepo`, `GuideRepo`, `ExeName`, `GuideFile`):

| Что | Где | Как |
|---|---|---|
| Сборка | `FactorioParanoidal/ParanoidalModpack`, ветка `pre_release_2.0` | git (папка `mods`) и REST API (список изменений) |
| Сам лаунчер | Releases `FactorioParanoidal/paranoidal-launcher` | `releases/latest/download/release.json`, файл `ParanoidalLauncher.exe` |
| Гайд | Releases `FactorioParanoidal/guide-to-the-paranoidal` | `releases/latest/download/release.json`, файл `Guide_to_the_Paranoidal.html` |

- `release.json` (один формат для лаунчера и гайда): `schema` 1, `product` (`launcher`/`guide`), `version` x.y.z,
  `date`, `file`, `size`, `sha256`, `changes` — все разделы CHANGELOG, новые сверху (`version`, `date`, `text`).
  Лаунчер пишет его через `tools/release-manifest.ps1`, гайд — `tools/release.py` в своём репозитории (CI).
- Файл качается по тегу этой версии (`releases/download/vX.Y.Z/<файл>`), сверяются размер и SHA-256, и только потом
  он заменяет старый. Это обычные загрузки файлов, лимит запросов к API (60 в час) они не тратят.
- Три проверки — сборка, лаунчер, гайд — идут одновременно при каждой проверке обновлений (`Releases.CheckAll`
  рядом с `SyncEngine.CheckStatus`). Без интернета — строка в журнале, ничего не блокируется.

## Самообновление (`src/SelfUpdate.cs`)

- Есть версия новее — окно со всеми версиями от установленной до новой и их изменениями, совет обновиться,
  «Обновить сейчас» / «Позже». Спрашивает при каждом запуске (и «Проверить обновления»), отказа «навсегда» нет. Пока
  идёт игра или операция, вопрос ждёт.
- Обновление: скачать в `ParanoidalLauncher.exe.new` → проверить SHA-256 и версию exe → запущенный exe
  переименовать в `.old` (перезаписать его нельзя, переименовать можно) → новый на его место → запустить с
  `--wait-pid <pid> --updated-from <версия>` → выйти. Новый процесс ждёт выхода старого (мьютекс), пишет
  «Лаунчер обновлён» и удаляет `.old`.
- Папка только для чтения (Program Files): файл качается во временную папку, а замену делает этот же exe с правами
  администратора (`--install-exe <файл> <папка>`, UAC). В окне — совет перенести папку игры в обычную папку.
- 1.1.0 и старше не умеют обновляться: им нужна ручная замена (анонс в Discord).

## Папка игры (`src/Relocation.cs`)

- Правильная работа гарантируется только из папки игры. При запуске (до распаковки MinGit) лаунчер находит игру:
  из настроек, иначе поиском. Если подходящих установок 2.0.77 Space Age несколько — спрашивает, какую выбрать.
- Лежит в другом месте — молча переезжает: копирует exe как `ParanoidalLauncher.exe` (если там нет той же или более
  новой версии — иначе запускается та) и свою папку данных (без MinGit, пути в `settings.ini` — абсолютные, новый
  exe делает их относительными), гайд; создаёт ярлык на рабочем столе; запускает копию с `--moved-from <старый exe>`
  и выходит. Копия удаляет со старого места только свой exe, `ParanoidalLauncher-data` (если там нет другого exe
  лаунчера) и копию гайда.
- Не получилось (Program Files и др.) — окно: правильная работа только из папки игры, «Перенести» просит права
  администратора, совет перенести игру в обычную папку. «Не сейчас» — спросит при следующем запуске. В режиме
  администратора данные идут в `%LOCALAPPDATA%\ParanoidalUpdater`.
- Игра не найдена или не 2.0.77 Space Age — переезда нет, пока игру не выберут («Выбрать…» тоже запускает переезд).
- Выключено: `PARANOIDAL_LAUNCHER_NO_RELOCATE=1`, задана `PARANOIDAL_LAUNCHER_DATA_DIR`, рядом с exe лежит
  `build-info.txt` (папка сборки `dist`/`obj`).
- «Ярлыки»: рабочий стол (настоящий путь, с учётом OneDrive) и «Пуск» → `Paranoidal` (лаунчер и гайд), через
  `IShellLink`.

## Гайд по сборке (`src/Guide.cs`)

- `Guide_to_the_Paranoidal.html` лежит рядом с exe (в папке игры), если туда нельзя писать — в папке данных.
  Версия — в `<meta name="guide-version">` в начале файла.
- Новая версия скачивается вместе с обновлением сборки; если сборка свежая, а гайд нет — статус «Доступно обновление
  гайда», «Обновить» качает только его. В журнале — выделенная строка «📖 Обновился гайд по сборке Paranoidal».
  При «Не менять версию» гайд не обновляется.
- «📖 Гайд» открывает только локальную копию; если её нет — скачивает и открывает.

## Сборка и тесты

- `powershell -ExecutionPolicy Bypass -File build.ps1` → `dist\ParanoidalLauncher.exe` и `dist\build-info.txt`
  (версия и SHA-256). Нужны Roslyn `csc.exe` (Visual Studio или Build Tools) и reference assemblies .NET Framework 4.8.
  Пробная сборка, не трогающая `dist\`: `-Out obj/dev/ParanoidalLauncher.exe` (из bash — с прямыми слешами).
- `tools\build-harness.ps1` → `obj\Harness.exe` — консольный прогон движка без окна (команды — в начале
  `tools\Harness.cs`): обновление, `--verify`, `--status`, `--rollback`, `--played`, `--info`, коммит как цель,
  `--loaddiag`, `--report`, `--parse-host`, `--paths`, `--releases`, `--guide`, `--download-launcher`, `--swap`,
  `--relocate`, `--cleanup-old`, `--shortcuts`, `--detect-all`.
  `--loaddiag-selftest tools\testdata\load-logs-2.0.77.zip` должен печатать `SELFTEST OK`.
- `tools\build-uishot.ps1` → `obj\UiShot.exe <папка> <ru|en> [папкаFactorio|-] [release.json]` рисует диалоги и
  главное окно в PNG через `PrintWindow`: окно за пределами экрана, без активации (фокус не отнимается).
  `tools\snap.ps1` снимает видимое окно.
- Переменные для тестов: `PARANOIDAL_LAUNCHER_DATA_DIR` — своя папка данных лаунчера (настройки и моды игрока не
  трогаются); `PARANOIDAL_LAUNCHER_TEST_OFFLINE=1` — git и GitHub ведут себя как без интернета;
  `PARANOIDAL_LAUNCHER_TEST_GITHUB=http://127.0.0.1:<порт>` — релизы лаунчера и гайда с локального сервера
  (`python -m http.server` над папкой `FactorioParanoidal/<repo>/releases/...`);
  `PARANOIDAL_LAUNCHER_TEST_SHORTCUTS=<папка>` — ярлыки туда, а не на рабочий стол;
  `PARANOIDAL_LAUNCHER_TEST_AUTO=<файл>` — окно вне экрана без активации, ответ «да» на самообновление и переезд,
  журнал дописывается в файл, закрытие после проверки (сквозные тесты перезапуска);
  `PARANOIDAL_LAUNCHER_NO_RELOCATE=1` — без переезда. Точные копии версий
  сборки для стенда: `git archive <коммит> mods | tar -x` из клона репозитория сборки.

## Где что лежит

- Данные лаунчера — в `ParanoidalLauncher-data` рядом с exe (`AppInfo.DataDir`). Если туда писать нельзя или exe
  лежит в папке модов — в `%LOCALAPPDATA%\ParanoidalUpdater`, причина пишется в журнал.
- `settings.ini`: `factorio`, `mods` (пути внутри папки exe хранятся относительными), `game-cache`, `pin`
  («Не менять версию»), `lang`, `launch-build`, `launch-build-prev`, `load-diag-key`.
- Там же `sync-log.txt`, `crash.txt`, `commits-cache.txt` (список изменений для офлайна), `load-diagnostics.txt`.
- Рядом с exe: `Guide_to_the_Paranoidal.html` (гайд), на время обновления — `ParanoidalLauncher.exe.new`/`.old` и
  `*.download`; лаунчер удаляет их сам.

## Язык

- Строки пишутся парой на месте: `Tr.T("русский", "English")`.
- По умолчанию русский, если язык Windows или регион — одна из 15 постсоветских стран; иначе английский.
- **Журнал, `sync-log.txt`, `crash.txt` и отчёт всегда на русском** — их читает команда сборки.

## Как хранится папка модов

- `<папка>\mods` — рабочие файлы, `<папка>\.paranoidal-git` — лёгкий git: частичный неглубокий клон без содержимого
  файлов, sparse checkout только `/mods/`. Папку, рядом с которой лежит `.git` (репозиторий разработчика), лаунчер
  не трогает.
- Файлы сравниваются и пишутся **побайтно** (`info/attributes`: `* -text`): Factorio в мультиплеере сравнивает моды
  побайтно, и копия с концами строк CRLF дала бы «Содержимое мода отличается».
- Полная побайтовая проверка идёт при первой синхронизации, по «Проверить файлы» и если индекс пропал. В остальных
  случаях git доверяет размеру и времени файла.
- Отлаживая эту папку вручную, ставьте `GIT_NO_LAZY_FETCH=1`, иначе git начнёт качать сборку по файлу.
- Особенность git: в таком клоне `git reset <коммит>` читает объекты файлов, которых нет. Поэтому
  `SyncEngine.ResetIndex` при ошибке пересоздаёт индекс. `read-tree` не подходит: он теряет sparse checkout.
- Git никогда не трогает `mod-list.json`, `mod-settings.dat`, zip-моды и моды, которые игрок решил оставить.
  В `mod-list.json` лаунчер меняет только дополнения: quality и elevated-rails включены, space-age выключен.

## Распознавание сборки (`src/Recognize.cs`)

- Сама сборка ради этого не меняется: лаунчер не пишет в моды.
- Если версия неизвестна или файлы отличаются, лаунчер смотрит `mods\zzzparanoidal\info.json`. Factorio 1.1 —
  старая сборка (Beta 8): только предупреждение.
- Иначе считает отпечаток папки в своём индексе `.paranoidal-git\fp-index` (в первый раз ~20 с на 950 МБ, потом
  только изменённые файлы) и сравнивает моды с версиями, которые уже знает.
- Точное совпадение — версия принимается без скачивания, файлы не меняются. Нет — показываются ближайшая версия
  и отличающиеся моды.
- С интернетом подкачивается история за 120 дней (~2 МБ, ~20 с в первый раз), и сравнение повторяется.
- Особенность GitHub: из фильтров по деревьям он принимает только `tree:0`.
- Если первая установка идёт поверх неопознанной сборки, лаунчер спрашивает подтверждение и качает только отличия.
- Скопированная целиком папка игры опознаётся без интернета (проверено: 2 с).

## Без интернета

- Проверка GitHub — одна попытка до 20 с. Нет связи — «Нет связи с GitHub», «ИГРАТЬ» доступна, список изменений
  берётся из кэша.
- Обновление без связи сдаётся быстро. Без интернета работают «Проверить файлы» (пока файлы целы), откат, отчёт,
  диагностика, распознавание, правка `mod-list.json` и `config.ini`.

## Откат и «Не менять версию» (`src/Rollback.cs`)

- Перед обновлением лаунчер сохраняет в `.paranoidal-git\rollback\` только те файлы старой версии, которые
  меняются или удаляются, и список добавленных. Не всю сборку.
- Откат ведёт к версии, с которой игра последний раз запускалась (два обновления подряд без игры — всё равно к ней).
  Работает без интернета, и «Вернуть» возвращает обратно.
- «Не менять версию» отключает обновление. «Версия хоста…» принимает строку «Скопировать версию» хоста, переходит на
  его версию (качается разница) и включает «Не менять версию».

## Диагностика загрузки (`src/LoadDiag.cs`)

- После выхода из игры и при старте лаунчер читает `factorio-current.log` и `factorio-previous.log` и пишет одну
  строку: время до меню, кэш данных ✔/✖, кэш атласа ✔/✖ и причину. Подробности — в подсказке и журнале.
- Правила и строки лога — `docs/factorio-load-cache.md`.

## Отчёт о проблеме (`src/Report.cs`)

- ZIP на рабочий стол, не больше 20 МБ (лимит Discord): версия и состояние, логи игры, `config.ini`,
  `mod-list.json`, `mod-settings.dat`, моды не из сборки, изменённые файлы сборки, журналы лаунчера, свежие дампы
  падений. По желанию — сейв (последний, последнее автосохранение или свой), если влезает.
- **Никогда** не кладётся `player-data.json` (там токен аккаунта Factorio). Имя пользователя в путях заменяется на
  `%USERPROFILE%` / `%USERNAME%`.

## Кэш загрузки игры (`src/GameConfig.cs`)

- Перед каждым запуском (галочка «Кэш загрузки игры», включена по умолчанию) лаунчер ставит `true` в
  `cache-prototype-data`, `cache-sprite-atlas` и `compress-sprite-atlas-cache` того `config.ini`, который игра читает
  сама (по `config-path.cfg`, иначе `%APPDATA%\Factorio`).
- Меняются только эти ключи, остальной файл как был; копия до первой правки — `config.ini.paranoidal-backup`. Пока
  игра запущена, файл не трогается (она перезаписывает его при выходе).
- Моды с зависимостью `~` не дают Factorio 2.0.77 использовать кэш данных — лаунчер предупреждает о них.
